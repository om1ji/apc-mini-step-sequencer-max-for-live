# apc-mini-step-sequencer-max-for-live

Драм-секвенсор для Max for Live под AKAI APC mini mk2. Сетка падов редактирует паттерн, кнопки под ней выбирают барабан, фейдеры сводят Drum Rack, а панель устройства показывает весь паттерн прямо в цепочке устройств Live.

Это MIDI-эффект: он отправляет ноты в Drum Rack, который стоит после него, поэтому сэмплы, эффекты и группы глушения остаются родными для Live. Есть парный проект, который делает то же самое отдельным VST3-плагином на Rust: [apc-mini-step-sequencer](https://github.com/om1ji/apc-mini-step-sequencer).

## Как это работает

| Элемент | Назначение |
| --- | --- |
| Два верхних ряда падов | 16 шагов одного такта по 1/16: шаги 1–8 в верхнем ряду, 9–16 — во втором сверху |
| Кнопки под сеткой | выбор барабана, который показан на сетке: кнопка 1 — пэд C1 в Drum Rack, кнопка 8 — G1 |
| Фейдеры 1–8 | громкость пэдов Drum Rack C1–G1 |
| Фейдер 9 | громкость дорожки |
| Кнопки справа, нижние шесть рядов падов | не задействованы |

Цвета падов: серый — шаг паттерна, жёлтый — включённый шаг, зелёный — шаг, который играет сейчас. Кнопка выбранного барабана горит. Звучат все восемь барабанов одновременно.

Панель устройства показывает все восемь барабанов × 16 шагов. Щелчок по клетке переключает шаг, щелчок по номеру барабана выбирает его на контроллере.

Внутри устройства:

- **`apcseq.js`** получает нажатия и движения фейдеров из `[midiin]` → `[midiparse]`, хранит паттерн и записывает в `[coll]` по строке на шаг: какие из восьми барабанов звучат на этом шаге.
- **Счётчик шагов** собран из обычных объектов Max: `[metro 16n @quantize 16n]` опрашивает `[transport]`, число тиков (480 на долю) превращается в номер шага, `[coll]` отдаёт строку этого шага, и включённые барабаны уходят через `[makenote 100 100]` → `[noteout]` нотами 36–43.
- **Подсветку** отправляет `apcseq.js` через `send_midi` у Control Surface MaxForLive — только для изменившихся падов.
- **Громкость** меняется через Live API, не чаще 30 раз в секунду.
- **Паттерн** хранится в проекте Live как скрытый параметр-блоб: `[pattr pattern @bindto apcjs]` с `parameter_type` 3.

## Почему так устроено

- **Ноты играют объекты Max, а не JavaScript.** `[js]` работает в низкоприоритетном потоке Max, и ноты из него плавали бы по времени. Скрипт только обновляет `[coll]`, а цепочка в потоке планировщика читает его на каждом шаге.
- **Нажатия приходят через MIDI-вход дорожки.** Первая версия регистрировала пады в Control Surface MaxForLive (`register_midi_control`, `grab_control`) и наблюдала их `value`. В Live 12.0.5 ни одно нажатие так и не дошло до устройства. Чтение входа дорожки через `[midiin]` работает, и так же устроен фирменный набор Ableton *APC Step Sequencer*.
- **Подсветка идёт через Control Surface MaxForLive.** Устройство Max for Live не может само открыть аппаратный MIDI-порт; `send_midi` у Control Surface — поддерживаемый способ отправить данные на выход контроллера.
- **Движения фейдеров склеиваются, а параметры громкости запоминаются.** Первая версия на каждое сообщение CC заново искала дорожку и Drum Rack через Live API. Если двинуть все девять фейдеров разом, Live зависал на несколько секунд. Теперь применяется только последнее значение каждого фейдера раз в 33 мс, а параметры ищутся заново, только когда на дорожке меняется список устройств.
- **Номер ноты считается арифметикой, а не через `if`.** В `[expr]` у Max нет `if()` (в Pure Data есть), поэтому `($i2 == 1) * ($i1 + 37) - 1` даёт ноту для включённого барабана и `-1` для выключенного, а `[sel -1]` её отбрасывает.
- **Патч генерирует [`build.py`](build.py),** а не редактор Max. Файл `.amxd` — это короткий бинарный заголовок и JSON патча; патч в виде кода видно в diff.

## Структура репозитория

```
apcseq.js            логика секвенсора, вход с контроллера, подсветка, громкость, сохранение паттерна
apcseq_ui.js         jsui: сетка 8 × 16 в панели устройства
build.py             собирает "APC Seq.amxd" и кладёт его со скриптами в User Library
test/apcseq.test.js  тесты логики в Node с заглушками Max и Live API
docs/diagrams/       исходник и интерактивная схема archify
```

## Что понадобится

- AKAI APC mini mk2.
- Ableton Live 12 Suite или Standard с Max for Live. Проверено в Live 12.0.5 (встроенный Max 8.6.2) на macOS 26.
- Python 3 для сборки устройства.
- Node.js — только для тестов.

`build.py` берёт пустой шаблон *Max MIDI Effect* из `/Applications/Ableton Live 12 Suite.app`. Если у вас другая редакция или Live установлен в другое место, поправьте `TEMPLATE` в начале скрипта.

## Сборка и установка

```bash
python3 build.py
```

Скрипт кладёт `APC Seq.amxd`, `apcseq.js` и `apcseq_ui.js` в `~/Music/Ableton/User Library/Presets/MIDI Effects/Max MIDI Effect/APC Seq/`. Скрипты должны лежать рядом с устройством: оно не заморожено, и Max ищет их в папке устройства.

## Настройка Ableton Live

1. **Settings → Link, Tempo & MIDI:**
   - в свободном слоте **Control Surface** выберите **MaxForLive**, Input и Output — **APC mini mk2 (Control)**;
   - у входного порта **APC mini mk2 (Control)** включите **Track**.
   - Не оставляйте **APC mini mk2** выбранным в Control Surface: скрипт Live будет перерисовывать пады.
2. Создайте MIDI-дорожку: **MIDI From** — **APC mini mk2 (Control)**, **Monitor** — **In**.
3. Перетащите на дорожку **User Library → MIDI Effects → Max MIDI Effect → APC Seq**, а после него **Drum Rack** с сэмплами на пэдах C1–G1.
4. Нажмите Play в Live и включите шаги на двух верхних рядах.

## Использование

Выберите барабан кнопкой под сеткой (или его номером в панели устройства) и включайте шаги на двух верхних рядах или в панели. Фейдеры 1–8 управляют громкостью пэдов Drum Rack, фейдер 9 — громкостью дорожки; фейдер в верхнем положении — 0 дБ. У пэда Drum Rack без сэмпла нет громкости, которую можно задать; положите на него сэмпл, и фейдер подхватит его при следующем движении.

Шаги отправляют ноты с velocity 100 и длительностью 100 мс.

## Тесты

```bash
node test/apcseq.test.js
```

Тест запускает `apcseq.js` с заглушками Max и Live API и проверяет раскладку шагов на пады и обратно, выбор дорожки, переключение шагов и строки, которые уходят в `[coll]`, сохранение и восстановление паттерна, а также то, какие параметры Live API меняют фейдеры. Патч, тайминг и работа с контроллером проверяются вручную в Live.

## Решение проблем

Сообщения устройства видно в окне Max: правый клик по заголовку устройства → **Open Max Window**. Сообщения скрипта начинаются с `APC Seq:`.

| Симптом или сообщение | Причина и что делать |
| --- | --- |
| Красная строка в устройстве: `Выберите Control Surface «MaxForLive» для APC mini mk2 в настройках Live` | Control Surface MaxForLive не выбран, подсветку отправить некуда. Настройте его, как в шаге 1, и добавьте устройство заново |
| Пады горят, но нажатия ничего не делают | дорожка не получает MIDI от APC: проверьте **Track** у входного порта, **MIDI From** и **Monitor In** |
| После старой сборки нажатия всё равно не работают | старая сборка зарегистрировала пады в Control Surface MaxForLive, и он продолжает их перехватывать; перезапустите Live |
| Сетка и подсветка работают, Drum Rack молчит | Drum Rack должен стоять после устройства на той же дорожке, с сэмплами на C1–G1 |
| Пады мигают или показывают цвета клипов | подсветкой управляет ещё и скрипт Control Surface APC mini mk2 или VST3-версия |
| Live зависает при движении фейдеров | сборка из времени, когда движения фейдеров ещё не склеивались; пересоберите и добавьте устройство заново |
| Окно Max сообщает, что не найден `apcseq.js` | скрипты лежат не рядом с `.amxd`; запустите `python3 build.py` ещё раз |

## Ограничения

- **Один такт, 16 шагов.** Номер шага — позиция транспорта по модулю 16 шестнадцатых от начала песни, поэтому в размерах, отличных от 4/4, паттерн перестаёт совпадать с тактом.
- **Устройство поглощает весь MIDI на своей дорожке.** Входящие ноты дальше не проходят, так что играть на этом же Drum Rack с другой клавиатуры через ту же дорожку не получится.
- **Восстановление паттерна из сохранённого проекта не проверено переоткрытием.** Паттерн пишется в скрытый параметр, код сохранения и восстановления покрыт тестами, но в Live это не проверялось.
- **Положение фейдеров неизвестно, пока их не сдвинуть**; при первом движении громкость скачком переходит в положение фейдера.
- **Устройство не заморожено.** Чтобы передать его одним файлом, откройте его в редакторе Max и выполните *Freeze Device*.
- **Не запускайте вместе с VST3-версией** на одном контроллере — обе перерисовывают пады.
