# apc-mini-step-sequencer-max-for-live

A Max for Live drum step sequencer for the AKAI APC mini mk2: the pad grid edits the pattern, the buttons under it pick the drum, the faders mix a Drum Rack, and the device's own panel shows the whole pattern inside Live's device chain.

It is a MIDI effect: it sends notes to a Drum Rack placed after it, so samples, effects and choke groups stay native Live. There is a sibling project that does the same thing as a standalone VST3 plugin in Rust: [apc-mini-step-sequencer](https://github.com/om1ji/apc-mini-step-sequencer).

## How it works

| Control | Role |
| --- | --- |
| Top two pad rows | 16 steps of one bar, 1/16 each: steps 1–8 on the top row, 9–16 on the row below |
| Buttons under the grid | select the drum shown on the grid: button 1 is Drum Rack pad C1, button 8 is G1 |
| Faders 1–8 | volume of Drum Rack pads C1–G1 |
| Fader 9 | volume of the track |
| Right-hand buttons, lower six pad rows | unused |

Pad colors: gray is a step in the pattern, yellow is an active step, green is the step playing now. The button of the selected drum is lit. All eight drums play at once.

The device panel shows all eight drums × 16 steps. Click a cell to toggle a step, click a drum number to select it on the controller.

Inside the device:

- **`apcseq.js`** receives presses and fader moves from `[midiin]` → `[midiparse]`, keeps the pattern, and writes one row per step into a `[coll]`: which of the eight drums sound on that step.
- **The step clock** is plain Max objects: `[metro 16n @quantize 16n]` bangs `[transport]`, its tick count (480 per beat) becomes a step number, `[coll]` returns that step's row, and active drums leave through `[makenote 100 100]` → `[noteout]` as notes 36–43.
- **LEDs** are sent by `apcseq.js` with `send_midi` on the MaxForLive control surface, only for pads that changed.
- **Volumes** are set through the Live API, at most 30 times a second.
- **The pattern** is stored in the Live set as a hidden blob parameter: `[pattr pattern @bindto apcjs]` with `parameter_type` 3.

## Why it is built this way

- **Notes are played by Max objects, not by JavaScript.** `[js]` runs in Max's low-priority thread, so notes sent from it would drift. The script only updates `[coll]`; the scheduler-thread chain reads it on each step.
- **Presses arrive through the track's MIDI input.** The first version registered the pads with the MaxForLive surface (`register_midi_control`, `grab_control`) and observed their `value`. In Live 12.0.5 no presses ever reached the device. Reading the track input with `[midiin]` works, and it is what Ableton's own *APC Step Sequencer* factory pack does.
- **LEDs go through the MaxForLive control surface.** A Max for Live device cannot open a hardware MIDI port itself; `send_midi` on a control surface is the supported way to reach the controller's output.
- **Fader updates are coalesced and the volume parameters cached.** The first version looked up the track and the Drum Rack through the Live API on every CC message. Moving all nine faders at once froze Live for seconds. Now only the latest value per fader is applied, every 33 ms, and the parameters are looked up again only when the track's device list changes.
- **The note formula is arithmetic, not `if`.** `[expr]` in Max has no `if()` (Pure Data's does), so `($i2 == 1) * ($i1 + 37) - 1` yields the note for an active drum and `-1` otherwise, which `[sel -1]` drops.
- **The patch is generated by [`build.py`](build.py),** not saved from the Max editor. A `.amxd` is a small binary header followed by the patcher JSON; keeping the patch as code makes it reviewable in git.

## Requirements

- AKAI APC mini mk2.
- Ableton Live 12 Suite, or Standard with Max for Live. Tested on Live 12.0.5 (bundled Max 8.6.2) on macOS 26.
- Python 3 to build the device.
- Node.js, only for the tests.

`build.py` takes the empty *Max MIDI Effect* template from `/Applications/Ableton Live 12 Suite.app`. With a different edition or install location, change `TEMPLATE` at the top of the script.

## Build and install

```bash
python3 build.py
```

It writes `APC Seq.amxd`, `apcseq.js` and `apcseq_ui.js` to `~/Music/Ableton/User Library/Presets/MIDI Effects/Max MIDI Effect/APC Seq/`. The scripts must stay next to the device: it is not frozen, and Max finds them by the device's folder.

## Setting up Ableton Live

1. **Settings → Link, Tempo & MIDI:**
   - in a free **Control Surface** slot choose **MaxForLive**, Input and Output **APC mini mk2 (Control)**;
   - for the input port **APC mini mk2 (Control)** turn **Track** on.
   - Do not keep **APC mini mk2** selected as a Control Surface: Live's script would repaint the pads.
2. Create a MIDI track: **MIDI From** — **APC mini mk2 (Control)**, **Monitor** — **In**.
3. Drop **User Library → MIDI Effects → Max MIDI Effect → APC Seq** on the track, then a **Drum Rack** after it with samples on pads C1–G1.
4. Press Play in Live and tap the top two pad rows.

## Usage

Pick a drum with the buttons under the grid (or its number in the device panel) and toggle steps on the top two rows or in the panel. Fader 1–8 set the Drum Rack pad volumes, fader 9 the track volume; a fader all the way up is 0 dB. A Drum Rack pad without a sample has no volume to set; drop a sample on it and the fader picks it up on the next move.

Steps send notes of velocity 100 and 100 ms length.

## Testing

```bash
node test/apcseq.test.js
```

It runs `apcseq.js` with stubbed Max and Live API objects and checks the step ↔ pad layout, track selection, step toggling and the rows written to `[coll]`, saving and restoring the pattern, and which Live API parameters the faders set. The patch, timing and the controller are checked by hand in Live.

## Troubleshooting

To see the device's messages, right-click its title bar → **Open Max Window**. Messages from the script start with `APC Seq:`.

| Symptom or message | Cause and fix |
| --- | --- |
| Red line in the device: `Выберите Control Surface «MaxForLive» для APC mini mk2 в настройках Live` | no MaxForLive control surface is selected; LEDs cannot be sent. Set it up as in step 1, then re-add the device |
| Pads light up but presses do nothing | the track does not receive the APC: check **Track** on the input port, **MIDI From** and **Monitor In** |
| Presses still do nothing after an older build | the old build registered the pads with the MaxForLive surface, which then keeps consuming them; restart Live |
| Grid and LEDs work, Drum Rack is silent | the Drum Rack must be after the device on the same track, with samples on C1–G1 |
| Pads flicker or show clip colors | the APC mini mk2 control surface script or the VST3 version is also driving the LEDs |
| Live freezes while moving faders | a build from before fader updates were coalesced; rebuild and re-add the device |
| Max Window reports that `apcseq.js` cannot be found | the scripts are not next to the `.amxd`; run `python3 build.py` again |

## Known limitations

- **One bar, 16 steps.** The step number is the transport position modulo 16 sixteenths, counted from the start of the song, so in meters other than 4/4 the pattern no longer lines up with the bar.
- **The device swallows all MIDI on its track.** It does not pass incoming notes through, so the Drum Rack cannot also be played from another keyboard on the same track.
- **Restoring the pattern from a saved set has not been checked by reopening a project.** The pattern is written to a hidden parameter, and the save/restore code is covered by the tests, but not verified in Live.
- **Fader positions are unknown until a fader moves**; the first move jumps the volume to the fader's position.
- **The device is not frozen.** To share it as a single file, open it in the Max editor and use *Freeze Device*.
- **Do not run it alongside the VST3 version** on the same controller — both repaint the pads.
